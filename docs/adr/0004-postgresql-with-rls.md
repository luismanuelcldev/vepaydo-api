# ADR 0004: PostgreSQL 16 with RLS (not SQL Server)

## Status
Accepted

## Context
The .NET scaffold generated by the project template referenced **SQL Server**
(`Microsoft.EntityFrameworkCore.SqlServer`, `Testcontainers.MsSql`). However, the
product's tenant isolation depends on PostgreSQL-specific features:

- Row Level Security with `FORCE ROW LEVEL SECURITY` and per-transaction context
  set via `set_config('app.tenant_id', ...)`.
- `SECURITY DEFINER` functions for the support console.
- `pg_trgm` (trigram similarity for the matching engine) and `citext` (case-insensitive email).
- Composite `(tenant_id, id)` foreign keys, partial/covering indexes, and a
  non-unique duplicate-reference index.
- An immutable `audit_events` table enforced by trigger.

The existing (and RLS-tested) migrations target PostgreSQL 16.

## Decision
Use **PostgreSQL 16** with the **Npgsql** EF Core provider
(`Npgsql.EntityFrameworkCore.PostgreSQL`) and `Testcontainers.PostgreSql` for tests.
Remove the SQL Server packages.

## Consequences
- RLS, `SECURITY DEFINER`, `set_config`, trigram search, and citext are available as required.
- The tested PostgreSQL migrations are reusable (translated to English names, see ADR 0005).
- Npgsql maps `citext`/`jsonb`/`inet`/`bytea`/`uuid` explicitly; this is handled in the EF model.
- `set_config(..., true)` is transaction-scoped, so every tenant operation must run
  inside a transaction (enforced fail-closed by the tenant-context runner).
